# PurpleRinn Skills

재사용 가능한 Codex 개발 플로우 스킬을 패키지 단위로 관리하는 저장소입니다. 첫 번째 패키지는 **Genie 개발 비서**입니다.

## Genie 소개

Genie는 제품 구상부터 설계, 구현 검토, QA, 보안, 배포와 배포 후 확인까지 개발 흐름을 관리하는 오케스트레이터입니다. 단순히 체크리스트를 완료 처리하는 것이 아니라 각 전문 스킬의 마지막 실행 시점, 대상 브랜치와 커밋, 결과, 이후 변경으로 검증이 낡았는지를 함께 보여줍니다.

주요 목적은 다음과 같습니다.

- 현재 개발 단계와 다음에 필요한 작업을 빠르게 확인한다.
- 이전 spec과 설계 판단, QA 범위, 보안 결정 등 중요한 결정 사항을 복기한다.
- 서로 다른 Codex 작업에서도 프로젝트 맥락을 이어간다.
- 마지막 QA나 배포 검증이 현재 코드에도 유효한지 판정한다.
- 프로젝트 구조에 맞는 스킬만 활성화하고 구조 변경 시 구성을 다시 점검한다.
- 실행 결과를 프로젝트의 `docs/genie`에 요약해 변경 이력을 남긴다.

Genie의 개발 방법론은 [garrytan/gstack](https://github.com/garrytan/gstack)에서 영감을 받았으며, Codex와 프로젝트별 실행 이력 관리에 맞게 재구성했습니다.

## 호출 방법

Genie는 명령어처럼 외우기보다 개발 비서에게 물어보듯 호출합니다.

```text
지니 설정
지니 프로젝트 설정
지니, 개발진행 단계 보여줘
지니, 지금 무엇을 해야 해?
지니, 마지막 QA가 언제였어?
지니, 이번 배포 준비 상태 확인해줘
지니, 결제 기능 진행 상황 보여줘
지니, 오래된 검증만 보여줘
지니, 다음 단계 실행해줘
지니, 지금까지 중요한 결정 정리해줘
```

조회 요청은 상태만 읽습니다. `실행해줘`, `수정해줘`, `배포해줘`처럼 변경 의도가 명확한 경우에만 해당 전문 스킬을 실행합니다.

## 동작 구조

```text
사용자
  └─ Genie 오케스트레이터
       ├─ 프로젝트와 Git 상태 확인
       ├─ .genie/config.json 활성 스킬 확인
       ├─ docs/genie 실행 이력 조회
       ├─ current / stale / failed / blocked 판정
       ├─ 다음 단계 추천
       └─ 선택한 전문 워커 실행
            └─ 결과 요약을 docs/genie/<skill-name>/ 에 기록
```

Genie를 처음 사용하는 프로젝트에서 `지니 설정` 또는 `지니 프로젝트 설정`을 요청하면 현재 저장소 구조를 검사하고 프로젝트 프로필과 활성 스킬을 제안합니다. 개발 단계를 먼저 요청했는데 설정이 없다면 다음 안내 후 설정 과정으로 전환합니다.

```text
Genie 프로젝트 설정이 없습니다. 설정부터 진행하겠습니다.
```

설정을 적용하면 Git으로 추적할 `.genie/config.json`과 실행 이력용 `docs/genie`를 생성합니다. 기록 폴더가 없으면 다음 안내를 표시합니다.

```text
Genie 실행 기록 폴더 docs/genie가 없습니다. 이번 실행부터 결과 요약을 보관하기 위해 폴더를 생성합니다.
```

전체 대화 원문은 저장하지 않습니다. 실행 목적, 결정, 결과, 검증, 미완료 항목과 다음 단계만 요약하며 Secret, 토큰, 쿠키, 개인정보 등은 기록하지 않습니다.

## 프로젝트 설정

Genie 스킬 전체는 Codex 전역에 한 번 설치하지만 프로젝트마다 실제 사용할 스킬은 `.genie/config.json`으로 제한합니다. 설정 시 `pubspec.yaml`, `package.json`, 프레임워크 의존성, 앱·어드민·서버·공용 패키지 경로를 확인해 `core`, `ui`, `flutter`, `web`, `backend`, `deploy` 트랙을 조합합니다.

```text
지니 설정
지니 프로젝트 설정
지니 현재 구조에 맞게 설정 다시 확인해줘
지니 활성 스킬 보여줘
```

설정 파일에는 다음 정보가 들어갑니다.

- 감지된 프로젝트 프로필과 기술
- Flutter, 웹, 웹 어드민, 백엔드와 공용 코드 경로
- 활성화된 필수·조건부 스킬 목록
- 스킬별 stale 판정 대상 경로
- 자동 감지에 대한 수동 활성·비활성 선택
- 마지막 구조 검사와 Genie 카탈로그 버전

설정이 이미 있어도 설정 호출 시 현재 구조를 다시 읽습니다. 새 앱·어드민·백엔드가 추가되거나 Genie 카탈로그에 새 스킬이 생기면 추가할 트랙과 스킬을 보여줍니다. 기존 수동 선택은 유지합니다.

역할은 다음처럼 분리됩니다.

```text
.genie/config.json       프로젝트별 활성 스킬과 경로 설정
.genie/deploy.json       프로젝트별 배포 절차 설정
docs/genie/              스킬 실행 결과와 대화 요약 이력
```

`.genie`와 `docs/genie`는 모두 프로젝트 Git에 포함하는 것을 권장합니다. Secret이나 인증 정보는 어느 설정·기록 파일에도 저장하지 않습니다.

## 포함된 스킬

| 단계 | 스킬 | 하는 일 | 일반적인 실행 시점 |
| --- | --- | --- | --- |
| 발견 | `genie-office-hours` | 사용자 문제와 전제를 질문하고 가장 작은 유효한 제품 범위를 찾습니다. | 프로젝트 시작 또는 큰 방향 전환 |
| 명세 | `genie-spec` | 목표, 범위, 제외 범위, 기술 현황, 수용 기준, 테스트와 롤백을 실행 가능한 명세로 만듭니다. | 기능 구현 전 |
| 제품 검토 | `genie-plan-ceo-review` | 확장·선택적 확장·범위 유지·축소 중 적절한 모드로 제품 가치와 범위를 재검토합니다. | 큰 기능의 spec 이후 |
| 기술 설계 | `genie-plan-eng-review` | 데이터 흐름, 상태, 오류, 보안, 성능, 마이그레이션과 테스트 계획을 고정합니다. | 구조·DB·외부 연동 변경 전 |
| 디자인 설계 | `genie-plan-design-review` | 사용자 흐름, 계층, 상태, 반응형, 접근성과 디자인 일관성을 검토합니다. | UI 작업 전 |
| 원인 조사 | `genie-investigate` | 증거와 가설을 통해 근본 원인을 찾고 검증된 경우에만 수정합니다. | 버그·장애 발생 시 |
| 코드 검토 | `genie-review` | diff를 기준으로 운영 버그, 범위 누락, 테스트와 문서 누락을 찾습니다. | 변경 완료 후 |
| 보고형 QA | `genie-qa-only` | 실제 사용자 관점의 브라우저 테스트를 수행하고 수정 없이 보고합니다. | 수정 전 기준선 또는 배포 전 |
| 보안 | `genie-cso` | OWASP·STRIDE·Secret·공급망·권한 경계를 읽기 전용으로 감사합니다. | 보안 민감 변경 또는 정기 점검 |
| 문서 동기화 | `genie-document-release` | 실제 변경과 README, 운영·스키마 문서의 불일치를 찾아 갱신합니다. | 기능 완료 또는 배포 후 |
| 수정형 QA | `genie-qa` | 브라우저에서 버그를 찾고 승인된 범위에서 수정·회귀 테스트·재검증합니다. | QA 보고 검토 후 |
| 성능 | `genie-benchmark` | 페이지 속도와 주요 성능 지표의 기준선을 만들고 전후를 비교합니다. | 배포 환경 확정 후, 주요 릴리스 전후 |
| 배포 감시 | `genie-canary` | 배포 후 핵심 URL, 콘솔 오류와 사용자 흐름을 확인하고 이상을 보고합니다. | 배포 직후 |
| 출하 | `genie-ship` | 테스트·검토·변경 정리·커밋·push·PR 흐름을 프로젝트 규칙에 맞게 수행합니다. | 배포 후보 확정 시 |
| 프로젝트 배포 | `genie-project-deploy` | 프로젝트마다 다른 배포 단계와 명령을 직접 설정하고 이후 실행·검증·리비전을 추적합니다. | 배포 환경이 정해진 뒤 |

### 프로젝트 배포를 별도 설정하는 이유

배포는 프로젝트마다 구조가 다릅니다. 어떤 프로젝트는 스테이징을 거쳐 운영으로 이동하고, 어떤 프로젝트는 PR merge 후 자동 배포되며, Cloud Run·Firebase Hosting·Vercel처럼 여러 단계를 연속해서 실행해야 할 수도 있습니다.

`genie-project-deploy`는 플랫폼이나 명령을 추측하지 않습니다. 먼저 다음 내용을 프로젝트에 직접 설정합니다.

- 개발·스테이징·운영 환경과 실행 순서
- 배포 전 필수 검증 명령
- 실제 배포 명령과 필요한 사용자 승인
- 배포 완료 판정 방법
- health check와 브라우저 확인 대상
- 실패 시 중단·롤백 절차
- 프로젝트 전용 배포 스킬이 있다면 그 연결 정보

배포 절차 자체는 `.genie/deploy.json`에 저장하고, 설정 이후 사용한 커밋, 배포 환경, 빌드·리비전 식별자와 검증 결과는 `docs/genie/project-deploy`에서 추적합니다. 설정이 없으면 임의로 배포하지 않고 `blocked` 상태로 안내합니다.

## 실행 이력

프로젝트 안에는 다음 구조로 요약이 쌓입니다.

```text
docs/genie/
├── _meta.json
├── spec/
│   └── 2026-08-07_143000+0900__payment-refund__abc1234.md
├── review/
├── qa-only/
├── project-deploy/
│   └── 2026-08-07_170000+0900__production__abc1234.md
└── canary/
```

실행 기록은 `passed`, `completed`, `partial`, `failed`, `blocked`, `not-applicable` 중 하나의 결과를 가집니다. 현재 코드와 동일하면 `current`, 관련 코드가 바뀌면 `stale`, 실행한 적이 없으면 `never-run`으로 표시합니다.

## 요구 사항

- OpenAI Codex
- Git 권장: 브랜치·커밋·변경 이후의 stale 판정에 사용
- Python 3.10 이상: Genie 이력 도구에 사용하며 외부 패키지는 필요 없음
- 브라우저 제어 도구: `qa`, `qa-only`, `benchmark`, `canary`에 필요
- 선택 사항: `gh` CLI, 프로젝트별 배포 CLI와 인증

브라우저나 배포 도구가 없으면 해당 스킬만 `blocked`로 기록하고 나머지 개발 흐름은 계속 사용할 수 있습니다.

## 설치

Codex에서 다음처럼 요청합니다.

```text
$skill-installer로 https://github.com/PurpleRinn/Skills/tree/main/genie 스킬을 설치해줘
```

또는 저장소를 복제한 뒤 PowerShell에서 실행합니다.

```powershell
.\scripts\install-genie.ps1
```

설치 위치는 기본적으로 `$CODEX_HOME/skills/genie`이며 `CODEX_HOME`이 없으면 사용자 홈의 `.codex/skills/genie`입니다. 설치 후 다음 Codex 대화부터 사용할 수 있습니다.

## 삭제

저장소를 복제한 위치에서 다음 명령을 실행합니다.

```powershell
.\scripts\uninstall-genie.ps1
```

스크립트는 삭제 대상이 Codex의 정확한 `skills/genie` 경로이고 Genie 스킬인지 확인한 뒤 승인을 요청합니다. 프로젝트에 생성된 `.genie` 설정과 `docs/genie` 실행 이력은 삭제하지 않습니다.
