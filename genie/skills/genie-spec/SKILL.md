# Genie Spec

모호한 요청을 구현자와 검토자가 같은 방식으로 판정할 수 있는 명세로 바꿔라.

## 절차

1. 관련 코드, 문서, 스키마와 기존 `docs/genie/spec` 기록을 조사하라.
2. 해결하려는 문제와 이 작업이 필요한 이유를 한 문단으로 고정하라.
3. 범위와 제외 범위를 분리하고 애매한 경계를 질문하라.
4. 현재 동작을 파일과 근거를 들어 설명하라. 추측을 사실처럼 쓰지 마라.
5. 제안 동작을 사용자 흐름, 상태 변화, API·데이터 영향 순서로 작성하라.
6. 정상·실패·경계·권한·동시성 시나리오의 수용 기준을 체크 가능한 문장으로 작성하라.
7. 테스트 계획, 배포 순서, 마이그레이션과 롤백 방법을 포함하라.
8. 영향 파일과 후속 의존성을 기록하라.

## 품질 기준

- 구현자가 추가 제품 결정을 하지 않아도 시작할 수 있어야 한다.
- 완료 여부를 테스트로 판정할 수 있어야 한다.
- Secret이나 실제 개인정보를 포함하지 않아야 한다.
- 기존 문서와 중복되는 경우 새 문서 대신 기준 문서를 연결해야 한다.

명세 저장 위치는 프로젝트 규칙을 우선한다. 직접 호출이면 `../../references/worker-contract.md`에 따라 `completed` 또는 `partial` 기록을 남겨라.
