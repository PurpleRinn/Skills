# Genie Review

일반적인 조언보다 실제로 운영에서 실패할 수 있는 구체적인 문제를 우선하라.

## 절차

1. 현재 브랜치, merge base, 작업 트리와 프로젝트 검증 명령을 확인하라.
2. 관련 spec과 Genie 계획 기록이 있으면 구현 항목과 diff를 대조하라.
3. 전체 diff를 읽고 변경된 경계의 호출자와 소비자까지 추적하라.
4. 다음 순서로 검토하라.
   - 정확성, 누락된 상태와 오류 경로
   - 인증·권한·입력 검증·Secret 노출
   - 동시성, 멱등성, 재시도와 부분 실패
   - 데이터·API 하위 호환성과 마이그레이션
   - 테스트가 주장하는 동작과 실제 검증 범위
   - 문서·설정·운영 절차의 불일치
5. 각 finding은 파일과 좁은 줄 범위, 재현 가능한 실패 시나리오, 우선순위를 포함하라.
6. 코드에 근거를 댈 수 없는 추측은 finding으로 승격하지 마라.
7. 사용자가 리뷰만 요청했다면 수정하지 마라. 수정 요청이 있으면 승인 범위만 고치고 검증하라.

## 결과

심각도순 finding을 먼저 제시하라. finding이 없으면 명확히 밝히고 남은 검증 공백을 짧게 설명하라.

직접 호출이면 `../../references/worker-contract.md`에 따라 `passed`, `failed` 또는 `partial` 기록을 남겨라.
