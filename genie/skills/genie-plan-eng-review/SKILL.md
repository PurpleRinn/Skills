# Genie Engineering Plan Review

숨은 가정을 데이터 흐름, 상태와 실패 경로로 드러내라.

## 절차

1. spec과 관련 코드를 읽고 현재 구조를 근거와 함께 설명하라.
2. 요청 → 검증 → 서비스 → 저장소 → 외부 시스템 → 응답의 데이터 흐름을 그려라.
3. 상태 모델과 허용된 전이를 정의하라. 불가능한 전이와 멱등성도 확인하라.
4. 정상 흐름뿐 아니라 입력 오류, 권한 실패, 타임아웃, 재시도, 부분 성공과 복구를 설계하라.
5. 인증·권한·Secret·개인정보·비용 증폭 경계를 검토하라.
6. 성능, 동시성, 캐시, 쿼리, 파일 크기와 외부 API 한계를 확인하라.
7. 스키마·Rules·마이그레이션·롤백·호환성 순서를 명시하라.
8. 단위·통합·계약·E2E 테스트 매트릭스를 작성하라.
9. 관측 로그, 지표와 운영자가 복구할 방법을 포함하라.

## 완료 조건

- 결정되지 않은 항목과 담당 결정자를 표시한다.
- 일방향 변경에는 명시적 승인과 롤백 대안을 둔다.
- 프로젝트 문서 동기화 대상을 나열한다.
- 구현 순서가 작은 검증 단위로 나뉘어 있다.

구현하지 마라. 직접 호출이면 `../../references/worker-contract.md`에 따라 `completed` 또는 `blocked` 기록을 남겨라.
