# Genie Document Release

문서를 새로 많이 만드는 것보다 현재 코드와 기준 문서의 불일치를 제거하라.

## 절차

1. 프로젝트 문서 규칙과 기준 문서를 확인하라.
2. 기준 브랜치 이후 diff, 관련 spec, 테스트와 배포 결과를 읽어 실제 변경을 요약하라.
3. 변경의 영향을 다음 네 유형으로 분류하라.
   - Reference: API, 설정, 스키마, 명령
   - How-to: 실제 작업 절차
   - Tutorial: 처음 성공하는 경로
   - Explanation: 설계 이유와 제약
4. README, 환경변수, 운영, 데이터 모델, 마이그레이션, 테스트와 사용자 가이드를 대조하라.
5. 코드로 확인할 수 없는 내용을 문서에 추측해서 추가하지 마라.
6. 중복 문서를 만들지 말고 source of truth를 갱신한 뒤 관련 문서를 연결하라.
7. 제거되거나 변경된 명령, 경로와 예시가 남아 있지 않은지 검색하라.
8. 문서 링크와 명령을 가능한 범위에서 검증하라.

## 결과

- 갱신한 문서와 변경 이유
- 확인했지만 변경하지 않은 문서
- 문서화되지 않은 잔여 영역
- 실제 검증 결과

직접 호출이면 `../../references/worker-contract.md`에 따라 `completed`, `partial` 또는 `blocked` 기록을 남겨라.
