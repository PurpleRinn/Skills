# Genie Canary

새 배포가 실제 사용자에게 건강한지 짧고 반복 가능한 검사로 확인하라.

## 절차

1. `docs/genie/project-deploy/config.json`과 최신 배포 기록에서 환경, URL, source commit과 리비전을 확인하라.
2. 설정이 없거나 배포 식별자를 연결할 수 없으면 임의 URL을 추측하지 말고 `blocked`로 보고하라.
3. health endpoint와 핵심 공개 페이지의 상태 코드, 응답 시간과 주요 헤더를 확인하라.
4. 브라우저에서 지정된 사용자 여정을 실행하고 콘솔·네트워크 오류를 확인하라.
5. 인증, 결제, 삭제 등 위험한 흐름은 설정된 안전한 smoke 범위만 수행하라.
6. 이전 카나리 또는 benchmark 기준과 비교해 신규 오류와 성능 악화를 구분하라.
7. 이상이 있으면 영향, 재현, 배포 리비전과 중단·롤백 권고를 즉시 제시하라.
8. 사용자가 지속 감시를 요청한 경우 지정된 시간과 간격 안에서만 반복하라.

코드를 자동 수정하거나 롤백하지 마라. 직접 호출이면 `../../references/worker-contract.md`에 따라 `passed`, `failed`, `partial` 또는 `blocked` 기록을 남겨라.
